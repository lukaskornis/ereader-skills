# Claude chat (Kobo verified 2026-11-18 with real replies; Kindle unverified)

Chat with Claude from the reader on the Claude subscription. Each chat is one HTML file in `<home>/Claude`, shown in a full-screen chat view and also readable as a book (fonts, margins, a table of contents of the questions).

## Use
- Shelf > Apps > Claude: the chats window, full screen in serif: New chat on top, then every chat newest first with its time (today) or day, about 12 a page, swipe for more. A tap opens the chat view; closing it comes back to the refreshed list. The gear opens Settings.
- Settings (gear in the chats window or the chat view header, or Tools menu > Claude > Settings), saved on every tap: opening prompt (multi-line box, leads each new chat), text size, line spacing and margin steppers, page numbers, context used and 5h limit On/Off, default model and effort, Mac relay address. Closing it re-lays out an open chat view.
- Tools menu > Claude: New chat (on-screen keyboard), Chats (opens the folder), Settings.
- The question box has a Model row (Haiku, Sonnet, Opus) and an Effort row (Low, Med, High, Max) above Cancel, Send and Long Send, ticked from the defaults (`model`, `effort`; Sonnet and Medium when unset). The pick applies to that question only and is kept on Retry and Edit. Long Send sends `length: "long"`: the relay swaps the system prompt's length line for an in-depth article of 2,000 to 5,000 words under h3 headings; it streams and pages like any reply, and Retry keeps it.
- Chat view: zen reading, text only, no scroll bar: one question and its reply at a time. The latest reply ends in follow-up links (two columns: Go deeper, Shorter, Example, Counterpoint, Simpler; then Ask… and New chat), part of the page HTML as `claude:` links hit-tested by the view itself, so they work even with "tap to follow links" off. Tap or swipe to turn pages; turning past a reply's end or start moves to the next or previous one. A tap on the top edge brings up the header (title, "Exchange n of m", book icon, gear, X); any other tap hides it. The book icon opens the chat as a book at that question; the X closes (and cancels a reply still being written). A small grey footer shows context used (left), the page within the reply (center, or "writing…") and the 5-hour limit (right), each switchable (`show_context`, `show_pages`, `show_five_hour`). Spread or pinch two fingers to make the text two points bigger or smaller (saved as `text_size`, 14 to 40). Text size, line spacing and margin come from `text_size`, `line_spacing`, `margin` in the config (Settings).
- A new question shows at once with "Thinking." gaining a dot each second, then the reply appears within about 2 s, a few words at a time. You stay on the page you are reading; only that page repaints when new text lands on it. Follow-ups appear once the reply is in.
- In the chats window and the chat view, swiping up or down along the left or right edge runs the reader's own edge gestures (Gestures plugin, reader set; frontlight on the left, warmth on the right by default), as in a book.
- In the chat view, hold a word or hold and drag over a passage to select it (HtmlBoxWidget's own selection, grey highlight). On release a row offers Copy, More on that (asked in this chat) and New chat (a new chat about it, naming this one); the highlight clears when the row closes. While a reply is being written only Copy is offered.
- Replies may hold tables, inline SVG diagrams and photos from the web (the relay fetches and embeds them, so the reader needs no web access; images it cannot fetch are dropped). In the chat view a diagram fills the text width (height from its viewBox, at most 80% of a page), and a figure that does not fit the rest of a page moves whole to the next one, since MuPDF would otherwise squeeze it to fit.
- In the book, the same steering links sit at the end; tapping one opens the chat view with the new reply.
- Select text: hold a word (dictionary popup) or hold and drag a phrase (highlight dialog). Both get Explain simply, More on that, Etymology, Similar concepts. The phrase and about 25 words around it go to Claude. In a chat it continues the chat; in any other book it starts a new chat about the passage, named after the book.
- Hold a chat in the chats window for Rename (changes the title inside the file; name and date stay, so its place in the list does too) or Delete (asks first; removes the file and its sidecar).
- Chats are plain files: rename, move or delete them in the file browser. The state rides inside the file, so a moved chat still continues.

## How it works
1. The subscription only works through Claude Code, so the Mac relays. `relay.py serve` (LaunchAgent `com.lukas.claudechat-relay`, port 8787, starts at login, restarts on crash; a watchdog agent `com.lukas.claudechat-relay-watchdog` reloads it within 5 minutes if it is ever unloaded) takes `POST /chat/stream {prompt, session_id, model, effort, opening, length}` with header `X-Key` and runs `claude -p --resume <session> --tools "" --system-prompt <book prose, HTML fragment> --output-format stream-json --include-partial-messages`. It answers one JSON object per line as Claude writes: `{delta}` for each piece of text, then `{session_id, html, usage}` or `{error}`. `effort` (low, medium, high, max) becomes `--effort`. `length: "long"` picks the long-form system prompt (same text, last line swapped); anything else gets the normal one. `opening` (the opening prompt from settings) leads the first question of a new chat only. `usage` is `{context, window, five_hour}`: context tokens from the last message, the model's window (learned from result lines, 1M default) and the 5-hour limit used, 0 to 1, from the CLI's `rate_limit_event`. That event comes right after the text ends, so the reply goes out on it, or on the result line if that comes first. If the reader hangs up, Claude is killed. `POST /chat` still returns the whole reply in one object.
2. It runs Claude with its own config dir (`~/.config/claudechat/claude-home`) plus `CLAUDE_CODE_DISABLE_CLAUDE_MDS` and `CLAUDE_CODE_DISABLE_AUTO_MEMORY` (the config dir alone still loaded `~/.claude/CLAUDE.md` and rules, 2026-11-20), so the global CLAUDE.md, hooks, plugins and output style never reach the chat, and with `CLAUDE_CODE_OAUTH_TOKEN` from the keychain item `claudechat-token` (made by `relay.py login`, which wraps `claude setup-token`; the normal CLI login expires and needs a browser).
3. launchd may not read `~/Documents`, so `install` copies the relay to `~/.local/bin/claudechat-relay` and the agent runs that copy. Re-run `install` after editing `relay.py`.
4. The plugin posts from a forked subprocess (`ffiutil.runInSubProcess` with a pipe) that copies the relay's bytes into the pipe; the UI reads what is there every 0.4 s and re-renders the reply so far in the chat view's `HtmlBoxWidget` (used bare, so there is no scroll bar) (MuPDF: cut-off tags, web images and an unfinished svg dropped), keeping the reader's page and refreshing only it (or just the footer's page count). On the final line it saves the chat.
4a. Before sending its final line the relay fetches every `<img src="http…">` (Wikimedia thumb URLs fall back to the original), shrinks it with `sips` to 1404 px (the Kobo screen width) JPEG and inlines it as a `data:` URI. MuPDF needs `@page { margin: 0 }` (default is about an inch) and sizes an svg by its width attribute, ignoring percentages, so the view strips svg width/height and sets `svg { width: 100% }` in CSS. The subprocess speaks raw HTTP over a socket because luasocket's `http.request` only hands over 2 KB blocks. Silence is tolerated for 60 s (a cold Mac can take ~15 s to start Claude Code). No answer at all (Wi-Fi waking, relay restarting) is retried after 2, 4, 8 and 16 s; any other failure shows Retry / Edit / Close. A typed question is kept in the `claudechat.unsent` setting until a reply arrives and prefills the next question box, so it survives failures, cancels and crashes.
5. The file's first line is `<!--claudechat {json}-->` with the title, session id and turns; the HTML below is rendered from it on each save. `--` inside the JSON is written as `--` so it can't end the comment.
6. `claude:` links are caught by wrapping the instance's `ReaderLink.onGotoLink`, before KOReader calls them invalid external links. Selection buttons use `ReaderHighlight:addToHighlightDialog` and `ReaderDictionary:addToDictButtons` (conditional rows).

## Router relay
`router/` holds a Rust relay for the OpenWrt router that calls the Claude API with an API key instead of the Mac's subscription: same protocol, about 1 MB of RAM, no Mac needed. See `router/router.md`. Switch a reader with `router/deploy.sh pair`, back with `relay.py pair`.

## Local relay (on the reader, verified 2026-11-21 on the Kobo Aura ONE)
The same Rust relay runs on the reader itself (armv7, 1.3 MB, about 0.4 MB RAM), no Mac or router needed. `local/deploy.sh [device]` builds it, installs it to `/mnt/onboard/.adds/claudechat/` with the subscription token from the Mac keychain, copies the plugin and pairs the reader with `127.0.0.1:8787`. The plugin runs `local/start.sh` at KOReader start and before each question when the host is 127.0.0.1; it brings loopback up (the Kobo boots with `lo` down, bind fails otherwise), binds 127.0.0.1 only and keeps state in `.adds/claudechat/data/`. Log: `/tmp/claudechat.log`. Works only while the reader's Wi-Fi is up. The first request after a start once failed with a TLS error and the next worked; the plugin retries. Back to the router: `router/deploy.sh pair`.

## Setup
- `relay.py login` once (browser opens), `relay.py install` (agent plus pairing every reader in `~/.config/ink/devices.json`), `relay.py pair kindle` for a reader that was off.
- The plugin: copy `claudechat.koplugin` to `<koreader>/plugins/`, restart KOReader.

## Pitfalls
- A stale screen (another book's status page) behind the question box came from widgets orphaned by repeated plugin reloads, not from the chat view: it never shows after `ink -d kobo restart`. Restart before judging repaint bugs.
- The Mac must be awake and on the same Wi-Fi. A DHCP change on the Mac needs `relay.py pair` again.
- `JSON.decode(s:gsub(...))` passes gsub's count as a second argument and fails silently: assign the gsub result to a local first (2026-11-18).
- Closing the reader with `ui:onClose()` from `ink eval` when no file manager is underneath quits KOReader, and the Kobo drops off Wi-Fi (2026-11-18).
- TitleBar holds one icon per side; the gear is an IconButton inserted first into the title bar's OverlapGroup with an `overlap_offset`, so it gets taps before the close button's wide tap zone.
- Mock relay for UI work without spending the subscription: a 20-line Python server on another port returning `{"session_id", "html"}`, then point the reader's host at it.
